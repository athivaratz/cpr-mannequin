# แก้ปัญหา

รวมปัญหาที่เจอบ่อยตอนประกอบและใช้งาน แต่ละหัวข้อบอกอาการ สาเหตุ และวิธีแก้
ถ้าแก้แล้วยังไม่ได้ ให้เก็บข้อความจาก Serial ไว้ด้วย เพราะบรรทัดที่ขึ้นต้นด้วย `#`
บอกสาเหตุได้ดี

> สื่อการเรียนรู้ ไม่ใช่เครื่องมือแพทย์

## HX711 ต้องใช้ 3.3 V บน ESP32

**อาการ**: ค่า กก. เพี้ยน อ่านไม่นิ่ง หรือ ESP32 รีบูต/ขาเสียหาย

HX711 ส่งระดับไฟที่ขา DT ตามไฟเลี้ยง VCC ถ้าเลี้ยง 5 V ขา DT จะเป็น 5 V
แต่ ESP32 รับได้เพียง 3.3 V ให้เปลี่ยน VCC ของ HX711 มาที่ขา 3V3 ของ ESP32
และใช้ GND ร่วมกัน

บน Nano ใช้ 5 V ได้ เพราะบอร์ดทำงานที่ 5 V

## HX711 อ่านได้ 10 ครั้ง/วินาที

**อาการ**: หน้าเว็บขึ้น **เซนเซอร์อ่านได้แค่ 10 ครั้ง/วินาที ดูวิธีแก้ในคู่มือ**
และ Serial ขึ้น `# HX711 is running at 10 SPS, see docs: RATE pin`

HX711 รุ่นทั่วไปต่อขา RATE ไว้กับ GND ทำให้ได้ 10 SPS
ที่อัตรากด 110 ครั้ง/นาที การกดหนึ่งครั้งใช้เวลาประมาณ 270 มิลลิวินาที
จึงได้ค่าเพียง 2–3 ตัวอย่าง และอาจพลาดยอดกด

### แก้เป็น 80 SPS

1. ถอดไฟเลี้ยงก่อน
2. หาขา RATE บนแผง HX711 (มักอยู่ใกล้ชิป) และดูว่ามีลายทองแดงต่อไปยัง GND
3. ยกขา RATE ออกจากแผง หรือตัดลายที่ต่อไป GND ให้ขาด
4. ต่อขา RATE ไปที่ DVDD หรือ VCC (บน ESP32 ใช้ 3.3 V)
5. ตรวจด้วยมัลติมิเตอร์ว่า RATE ไม่ต่อกับ GND แล้ว
6. เปิดเครื่องใหม่

หลังแก้ ที่แถบล่างของหน้าเว็บควรแสดงอัตราตัวอย่างประมาณ `80 SPS`
ถ้ายังขึ้น 10 SPS ให้ตรวจรอยบัดกรีและลายที่ตัดอีกครั้ง

การตัดลายบนแผงเป็นการแก้ฮาร์ดแวร์ ควรทำอย่างระวังหรือให้ผู้ที่มีประสบการณ์ช่วย

## อัปโหลด ESP32 ไม่ได้

**อาการ**: ขึ้นข้อความประมาณ `Failed to connect to ESP32` หรือ
`Wrong boot mode detected`

1. กดปุ่ม **BOOT** ค้างไว้
2. กดปุ่ม **EN** หรือ **RST** หนึ่งครั้ง แล้วปล่อย
3. ปล่อย **BOOT**
4. สั่งอัปโหลดใหม่

```
pio run -e esp32dev -t upload
```

บางบอร์ดต้องกด BOOT ค้างไว้จนขึ้นคำว่า `Connecting...` แล้วจึงปล่อย
ตรวจสาย USB ว่าเป็นสายที่ส่งข้อมูลได้ ไม่ใช่สายชาร์จอย่างเดียว
และเลือกพอร์ตให้ถูก

## Nano ใช้ bootloader เก่า

**อาการ**: อัปโหลดไม่ขึ้น หรือขึ้น timeout

บอร์ดโคลนราคาถูกจำนวนมากยังใช้ bootloader เก่า ให้ลอง

```
pio run -e nano_oldbl -t upload
```

`env:nano` ใช้ Optiboot (ใหม่) และ `env:nano_oldbl` ใช้ bootloader เก่า
โค้ดเหมือนกันทุกอย่าง ต่างแค่การอัปโหลด

## คอมพิวเตอร์ไม่เห็น Nano (CH340)

**อาการ**: ไม่มีพอร์ตให้เลือก

- ติดตั้งไดรเวอร์ CH340/CH341 สำหรับระบบปฏิบัติการของคุณ
- Windows: ดูใน Device Manager ว่ามีพอร์ต COM ใหม่ขึ้นมาหรือไม่
- Linux: โดยมากมีไดรเวอร์มาให้แล้ว ตรวจด้วย `ls /dev/ttyUSB*`
  และเพิ่มผู้ใช้เข้ากลุ่ม `dialout` ถ้าไม่มีสิทธิ์เข้าถึงพอร์ต
- macOS: ตรวจ `/dev/cu.usbserial-*` หรือ `/dev/cu.wchusbserial-*`
- ลองเปลี่ยนสาย USB หรือพอร์ต USB
- ปิดโปรแกรมอื่นที่ใช้พอร์ตอยู่ เช่น Serial Monitor หรือ Arduino IDE

## Serial ใช้ 115200 ไม่ใช่ 9600

**อาการ**: เปิด Serial Monitor แล้วเห็นตัวอักษรแปลก ๆ หรือข้อมูลขาด

สเก็ตช์เก่าใช้ 9600 แต่เฟิร์มแวร์นี้ใช้ **115200**
ตั้ง Serial Monitor ที่ 115200, 8 data bits, no parity, 1 stop bit
หน้าเว็บ Web Serial ก็ใช้ 115200 และตั้งให้อัตโนมัติ

ถ้าใช้คำสั่งเก่าจากสเก็ตช์เดิม เช่น `t`, `+`, `-`, `w` จะไม่ทำงาน
ให้ใช้คำสั่งใหม่ตาม [`PROTOCOL.md`](PROTOCOL.md) เช่น `tare`, `start`, `stop`

## โหลดเซลล์อ่านค่าเป็นลบ

**อาการ**: ตอนไม่มีของวาง ค่าไม่ใกล้ศูนย์ หรือตอนมีของกลับอ่านค่าลบ

1. วางหุ่นบนพื้นเรียบ เอามือออก แล้วสั่ง `tare`
2. วางของที่รู้น้ำหนัก แล้วสั่ง `cal weight <kg>` เช่น `cal weight 2.0`
3. ถ้ายังอ่านเป็นลบ ให้ถอดไฟแล้วสลับสาย **A+** กับ **A-**
4. เปิดเครื่อง ตั้งศูนย์และตั้งน้ำหนักใหม่

ตรวจด้วยว่าสาย E+ และ E- ไม่ได้สลับกับ A+ และ A-
และโหลดเซลล์ไม่ได้ถูกขันแน่นทั้งสองปลายจนงอไม่ได้

## ค่าศูนย์ลอย (drifting zero)

**อาการ**: ปล่อยมือแล้วค่า กก. ไม่กลับศูนย์ หรือค่อย ๆ เพี้ยนไป

- เปิดเครื่องทิ้งไว้ 2–3 นาทีให้อุณหภูมิคงที่ก่อนตั้งศูนย์
- วางบนพื้นที่ไม่สั่น และไม่มีลมจากพัดลมเป่าโดน
- ตรวจว่าไม่มีอะไรกดแผ่นกดตอนพัก
- ตรวจว่าสายโหลดเซลล์ไม่ถูกดึงหรือขยับตอนใช้งาน
- ฟองน้ำอาจคืนตัวช้า ให้รอแล้ว `tare` ใหม่
- ตั้งศูนย์ก่อนฝึกทุกครั้ง

ถ้าค่าเพี้ยนมากจนชนค่ากดเกิน ให้ตรวจตัวหยุดแข็งและแรงกดว่าเกินพิกัดหรือไม่

## หา VL53L0X ไม่พบ

**อาการ**: Serial ขึ้น `# VL53L0X not found` หรือ `# VL53L0X no reading`
หรือสั่ง `cal start` แล้วได้ `no tof`

- VL53L0X ในเฟิร์มแวร์นี้ใช้กับ ESP32
  ส่วน Nano build ปกติไม่มีความจำพอ จึงไม่มี ToF
- ตรวจ VIN และ GND
- ตรวจ SDA ที่ GPIO21 และ SCL ที่ GPIO22 ของ ESP32
- โมดูลส่วนใหญ่ใช้ที่อยู่ I²C `0x29` และไม่ควรมีอุปกรณ์อื่นชนที่อยู่
- ตรวจว่าไม่มีอะไรบังหน้าต่างเซนเซอร์ และมีรูให้ลำแสงผ่านฟองน้ำ
- ตรวจว่าแผ่นกดอยู่ในระยะที่เซนเซอร์อ่านได้ และไม่ได้เอียงจนสะท้อนกลับไม่พอ
- ถ้าเป็น `no reading` ให้ตรวจว่าระยะพักไม่ไกลเกินไป และเลนส์สะอาด

## Wi-Fi ไม่ขึ้น หรือเปิดหน้าเว็บไม่ได้

**อาการ**: มองไม่เห็น `CPR-Trainer-XXXX` หรือต่อแล้วเปิดหน้าเว็บไม่ขึ้น

- ESP32 เปิด Wi-Fi 2.4 GHz เท่านั้น โทรศัพท์หรือคอมพิวเตอร์ต้องรองรับ 2.4 GHz
- รอประมาณ 10–15 วินาทีหลังเปิดเครื่อง
- ตรวจ Serial ว่าไม่มี `# AP start failed`
- ตรวจว่าไฟเลี้ยงพอ และบอร์ดไม่รีบูตวน
- ต่อได้สูงสุด 4 เครื่อง ถ้ามีคนต่อเต็ม ให้ตัดเครื่องที่ไม่ใช้ก่อน
- ถ้าหน้า captive portal ไม่เด้ง ให้เปิดเบราว์เซอร์ไปที่ <http://192.168.4.1> เอง
- ปิด VPN และปิดข้อมูลมือถือชั่วคราว เพื่อไม่ให้เครื่องไปออกอินเทอร์เน็ตทางอื่น
- รหัสผ่านเริ่มต้นคือ `cprtrain123` ถ้าเคยเปลี่ยนด้วย `wifi pass`
  ต้องใช้รหัสใหม่และรีบูต

## Web Serial ใช้ไม่ได้

**อาการ**: การ์ด **สาย USB (Web Serial)** กดไม่ได้ หรือเปิดพอร์ตไม่สำเร็จ

- ใช้ Chrome หรือ Edge บนเดสก์ท็อป
  Firefox และ Safari ยังไม่รองรับ Web Serial
- เปิดหน้าจาก `http://localhost` หรือ `https://` ไม่ใช่เปิดไฟล์ตรง ๆ
  วิธีที่แนะนำคือรัน `python3 tools/devserver.py --port 8080`
  แล้วเปิด <http://localhost:8080/>
- ปิด Serial Monitor หรือโปรแกรมอื่นที่จับพอร์ตอยู่
- ตรวจสาย USB และไดรเวอร์ CH340 สำหรับ Nano
- บน Linux ตรวจสิทธิ์เข้าถึงพอร์ต (`dialout`)
- ถ้าเลือกพอร์ตผิด ให้ตัดการเชื่อมต่อแล้วเลือกใหม่

## หน้าเว็บขึ้นว่าเซนเซอร์อ่านได้แค่ 10 ครั้ง/วินาที

ข้อความเต็มคือ **เซนเซอร์อ่านได้แค่ 10 ครั้ง/วินาที ดูวิธีแก้ในคู่มือ**

แปลว่า HX711 ยังทำงานที่ 10 SPS ให้ทำตามหัวข้อ
"HX711 อ่านได้ 10 ครั้ง/วินาที" ด้านบน

ที่ 10 SPS ยอดกดอาจถูกพลาด ทำให้ความลึกถูกประเมินต่ำและคะแนนต่ำกว่าความจริง
ในไฟล์ตัวอย่าง `recordings/lowsps_good.jsonl` การกดที่ดีถูกจัดเป็น "ตื้นไป"
เพราะเหตุนี้

## ยังไม่ได้ผลสรุป

**อาการ**: กด **จบรอบ** แล้วขึ้น **ยังไม่ได้รับผลสรุปจากหุ่น**

- ตรวจว่าสายหรือ Wi-Fi ยังต่ออยู่
- รออีกเล็กน้อย เพราะคำสั่ง `stop` ต้องผ่านคิวไปถึง task ที่อ่านเซนเซอร์
- ถ้าหลุดกลางรอบ ให้เชื่อมต่อใหม่แล้วเริ่มรอบใหม่
- ถ้าไม่กดต่อ 30 วินาที หุ่นจะจบรอบเองและส่งผลสรุปให้
